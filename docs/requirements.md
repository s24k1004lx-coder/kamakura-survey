# 要件定義書：鎌倉コミュニティ通貨アンケート入力・集計システム

## 1. プロジェクト概要

### 1.1 目的
鎌倉市のコミュニティ通貨「まちのコイン鎌倉（通貨名：クルッポ）」が観光客に利用されない要因を調査する卒業研究のため、街頭対面アンケートの入力・集計・分類を行うWebアプリケーションを開発する。

### 1.2 調査概要
- **調査方法**: 鎌倉の街頭で観光客に対面でアンケートを実施
- **目標サンプル数**: n=100程度
- **調査対象**: 観光客（一人客およびグループ客）
- **調査員**: 開発者本人（1名）

### 1.3 システムの位置づけ
- 調査員がスマートフォンから回答を入力し、集計・分析まで完結するツール
- 研究データを扱うため、データの消失・改ざん防止を最優先とする

## 2. システム要件

### 2.1 前提条件・制約
| 項目 | 内容 |
|---|---|
| 操作環境 | スマートフォンのブラウザのみで全操作（入力・集計・分類） |
| 画面設計基準 | スマホ縦長レイアウト |
| AI/ML | **一切使用しない**。集計・検定・分類はすべて決定的処理（同一データ→同一結果） |
| 設問の可変性 | 設問・選択肢・分岐条件は `config/questions.yaml` で定義し、YAML変更のみで追従 |
| 分類カテゴリの可変性 | `config/codebook.yaml` で定義 |
| データ保全 | 消失・改ざん防止が最優先。論理削除・変更履歴を記録 |
| 個人情報 | 回答者の氏名・連絡先等は収集しない |
| 秘密情報 | DB接続情報・アプリパスワードはsecretsで管理し、コード・Gitに含めない |

### 2.2 技術構成
| 要素 | 採用技術 | 選定理由 |
|---|---|---|
| フロントエンド/アプリ | Streamlit | Python完結、開発者が修正容易、無料デプロイ可能 |
| データベース | Supabase (PostgreSQL) | トランザクション・外部キー制約によるデータ整合性、論理削除・履歴の自然な実装 |
| デプロイ | Streamlit Community Cloud | 無料、スマホからHTTPSアクセス可能 |
| グラフ描画 | matplotlib + japanize-matplotlib | 論文用PNG出力対応、日本語フォント対応 |
| 統計処理 | scipy | カイ二乗検定・フィッシャー正確確率検定 |

### 2.3 主要ライブラリ
| ライブラリ | バージョン | 用途 |

## 3. データベース設計

### 3.1 設計方針
- **EAV（Entity-Attribute-Value）パターン**を採用
- 1行 = 1つの設問への1つの回答として格納
- YAMLの設問変更時にDBスキーマの変更が不要
- CSVエクスポート時にピボットして「1行1人」の横持ちに変換可能

### 3.2 テーブル定義

#### survey_groups（グループ単位の調査記録）
| カラム | 型 | 説明 |
|---|---|---|
| id | UUID (PK) | グループID。自動生成 |
| created_at | timestamptz | 入力日時。自動付与 |
| location | text | 調査地点（YAMLの選択肢から選択） |
| survey_type | text | 'pretest' / 'main' |
| input_method | text | 'field'（現地入力） / 'transcription'（紙からの転記） |
| group_size | int | グループ人数（一人客は1） |
| is_deleted | bool | 論理削除フラグ（デフォルト: false） |
| deleted_at | timestamptz | 削除日時（null = 未削除） |
| session_draft | jsonb | 入力途中の下書き保存用（保存完了後にnull） |

#### responses（メンバーごとの回答ヘッダ）
| カラム | 型 | 説明 |
|---|---|---|
| id | UUID (PK) | 回答ID。自動生成 |
| group_id | UUID (FK) | → survey_groups.id |
| member_number | int | グループ内の番号（1, 2, 3...） |
| conformity_flag | bool | 同調の可能性フラグ（デフォルト: false） |
| is_deleted | bool | 論理削除フラグ |
| deleted_at | timestamptz | 削除日時 |
| branch | text | 分岐先（'A' / 'B' / null） |

#### answers（個々の回答値）
| カラム | 型 | 説明 |
|---|---|---|
| id | UUID (PK) | 回答値ID。自動生成 |
| response_id | UUID (FK) | → responses.id |
| question_id | text | YAMLのキー（例: 'Q1', 'Q6_A'） |
| value | text | 単一選択・自由記述の値 |
| values | text[] | 複数選択の値（PostgreSQL配列型） |

#### edit_history（変更履歴）
| カラム | 型 | 説明 |
|---|---|---|
| id | UUID (PK) | 履歴ID。自動生成 |
| target_type | text | 'group' / 'response' / 'answer' |
| target_id | UUID | 対象レコードのID |
| action | text | 'create' / 'update' / 'delete' / 'restore' |
| old_value | jsonb | 変更前の値（createの場合はnull） |
| new_value | jsonb | 変更後の値（deleteの場合はnull） |
| changed_at | timestamptz | 変更日時 |
| changed_by | text | 変更者ID（当面は'surveyor'固定） |

#### classifications（自由記述の分類結果）
| カラム | 型 | 説明 |
|---|---|---|
| id | UUID (PK) | 分類ID。自動生成 |
| answer_id | UUID (FK) | → answers.id |
| categories | text[] | 分類カテゴリ（複数可） |
| status | text | 'classified' / 'pending' / 'new_category' |
| memo | text | 新カテゴリ候補のメモ |
| classifier_id | text | 分類者ID（κ係数計算用） |
| classified_at | timestamptz | 分類日時 |

### 3.3 ER図（論理構造）
```
survey_groups (1) ──< (N) responses (1) ──< (N) answers (1) ──< (0..1) classifications
                                                     │
                                               edit_history（全テーブル対象）
```

## 4. 機能要件

### 4.1 回答入力画面（Phase 2で実装）

#### 4.1.1 共通仕様
- 調査員が回答者の答えを聞きながら入力する想定
- 大きなボタン型の選択肢（片手タップ可能なサイズ）
- 設問の分岐ロジック: `questions.yaml` の `branch` 属性に基づいて表示を制御
- 必須項目の未入力チェック、分岐と矛盾する入力の防止
- 保存時に自動付与される情報:
  - 回答ID（UUID）
  - 日時（タイムスタンプ）
  - 調査地点（入力開始時に選択。選択肢はYAMLで定義）
  - 調査区分（プレテスト／本調査）
  - 入力方法（現地入力／紙からの転記）
- 保存後、即座に次の回答者（グループ）の入力画面に戻る
- 入力済み件数（人数・グループ数）を画面上部に常時表示

#### 4.1.2 一人／グループの切り替え
- 入力開始時に「一人」か「グループ（人数: 2〜6人）」を選択
- **一人の場合**: 1人分の回答を1画面ずつ素早く入力
- **グループの場合**:
  - 1設問につき人数分の回答欄を表示（スマホでは縦カード形式）
  - 「全員同じ」ボタンで1人目の回答を他メンバーにコピー（コピー後の個別修正可）
  - 分岐はメンバーごとに判定（同画面でメンバーごとに必要な設問のみ表示）
  - 保存はグループ単位でまとめて実行
  - 入力途中のデータはDBの `session_draft` に自動保存（画面を閉じても復元可能）
- 各回答に自動付与:
  - グループID（同一グループ共通）
  - グループ人数
  - グループ内メンバー番号（1, 2, 3...）
- メンバーごとに「同調の可能性あり」フラグを任意で設定可能

#### 4.1.3 直近の入力確認・修正・削除
- 直近の入力を一覧表示し、確認・修正・削除が可能
- 削除は論理削除（`is_deleted = true`）で復元可能
- 修正・削除の操作は `edit_history` テーブルに記録

### 4.1.4 調査記録機能（Phase 2.5で実装。プレテスト・本調査共通）
回答そのもの以外に、調査の実施状況を記録する。
- **声かけカウンター**: 入力画面の上部に常時表示
  - 「断られた」ボタンで断られた件数+1（押し間違い用に「戻す」= 今日の最新の1件を論理削除）
  - 回答を保存すると「回答」が自動で+1（保存済みグループ数から算出。紙からの転記は除外）
  - 「声かけ◯件／回答◯件／回答率◯%」を表示（今日の分）
  - 断られた記録にも日時・調査地点・調査区分を付ける（`refusals` テーブル）
- **所要時間の自動計測**: 「入力開始」と「保存」の時刻を記録し、所要時間（秒）を `survey_groups.duration_sec` に保存。集計画面に平均・中央値・最大を表示
- **設問ごとのつまずきフラグ**: 各設問に「⚠️ つまずき」トグル、任意で一言メモ。`survey_groups.stumble_flags` に {設問ID: メモ} で保存。集計画面に「つまずきが多かった設問ランキング」を表示
- **調査日メモ**: 天気・混雑具合・気づいたことを1日1件（`survey_day_notes` テーブル）
- **回答方式**: 調査員が読み上げ／本人が記入 を回答者ごとに記録（`responses.response_mode`）
- 既存DBへの反映は `docs/migration_phase2_5.sql`

### 4.2 集計画面（Phase 3で実装）

#### 4.2.1 集計内容
「集計を実行」ボタン1つで以下をまとめて表示:
- **単純集計**: 各設問の度数・割合、棒グラフ
- **グループ人数の分布**
- **クロス集計**: 居住地別、来訪回数別、年代別
- **想起の比較**: 純粋想起（Q3）と助成想起（Q4）の比較
- **利用意向の分布**: 分岐B・Q6-Bの集計
- **統計検定**: カイ二乗検定（期待度数が小さい場合はフィッシャーの正確確率検定に自動切替、その旨を表示）
- **自由記述の分類結果集計**

#### 4.2.2 絞り込み条件
- 調査区分（プレテスト／本調査）
- 鎌倉市内在住者を「住民」として観光客と分離
- 回答者の範囲:
  - 全回答者
  - 一人客のみ
  - グループ代表1人のみ（メンバー番号1、またはランダム抽出。ランダム時は乱数シード固定・表示で再現可能）
  - 同調フラグのある回答を除外

#### 4.2.3 感度分析
- 「全回答者」と「グループ代表1人のみ」の集計結果・検定結果を並列比較表示
- グループ回答を含む場合、検定結果の横に「回答の独立性が完全には保証されない」旨の注記を表示

#### 4.2.4 出力
- スマホで見やすいレイアウト、日本語フォント対応グラフ
- 集計結果のCSV・HTMLレポートダウンロード
- 論文用の図（PNG）を個別ダウンロード

### 4.3 自由記述の手動分類画面（Phase 4で実装）
- 分類カテゴリ・定義は `config/codebook.yaml` で定義（設問ごとにカテゴリ保持）
- 未分類の自由記述を1件ずつ表示し、カテゴリボタンをタップして分類（複数カテゴリ可）
- 各カテゴリボタン近くに定義を表示（判断ブレの低減）
- 「保留」「該当なし（新カテゴリ候補）」を選択可能。新カテゴリ候補にはメモを残せる
- 分類済み回答の見直し・変更が可能
- 未分類件数・分類済み件数を表示
- 分類結果に `classifier_id` を持たせ、将来のκ係数計算に備える

### 4.4 κ係数計算（Phase 5で実装・任意）
- 複数の分類者が同じ回答を分類した結果から、コーエンのκ係数を計算
- 分類者ペアごとの一致率を表示

### 4.5 データ管理・認証
- アプリ全体にパスワード認証
- 全データのCSV一括エクスポート（バックアップ用）
- 回答者の個人情報は収集しない設計

## 10. ディレクトリ構成

```
kamakura-survey/
├── .streamlit/
│   ├── config.toml          （テーマ・レイアウト設定）
│   └── secrets.toml         （※gitignore。DB接続情報・アプリパスワード）
├── config/
│   ├── questions.yaml        （設問・選択肢・分岐条件の定義）
│   └── codebook.yaml         （自由記述の分類カテゴリ定義）
├── docs/
│   └── requirements.md       （本書）
├── app.py                     （エントリポイント。認証＋ページルーティング）
├── pages/
│   ├── 1_input.py             （回答入力画面）
│   ├── 2_review.py            （直近の入力確認・修正・削除）
│   ├── 3_aggregate.py         （集計・検定・グラフ）
│   └── 4_classify.py          （自由記述の手動分類）
├── lib/
│   ├── db.py                  （Supabase CRUD操作）
│   ├── auth.py                （パスワード認証）
│   ├── config_loader.py       （YAML読み込み・バリデーション）
│   ├── stats.py               （集計・検定ロジック）
│   └── export.py              （CSV・HTML・PNGエクスポート）
├── tests/
│   ├── test_stats.py          （集計・検定の単体テスト）
│   ├── test_config_loader.py  （YAML読み込みテスト）
│   └── generate_dummy.py      （ダミーデータ生成スクリプト）
├── .gitignore
├── requirements.txt
└── README.md
```
