# 鎌倉コミュニティ通貨アンケートシステム

鎌倉市のコミュニティ通貨「まちのコイン鎌倉（クルッポ）」の利用・非利用要因を調査する卒業研究用のアンケート入力・集計・分類Webアプリケーション。

## 機能

- **回答入力**: スマートフォンから街頭で対面アンケートを入力（一人客・グループ客対応）
- **調査記録**: 声かけカウンター（断られた件数・回答率）、所要時間の自動計測、設問ごとのつまずきフラグ、調査日メモ、回答方式の記録
- **集計・分析**: 単純集計・クロス集計・カイ二乗検定・感度分析をワンクリックで実行
- **自由記述分類**: コードブックに基づく手動分類
- **データ管理**: CSVエクスポート・バックアップ

## セットアップ

### 1. 依存ライブラリのインストール
```bash
pip install -r requirements.txt
```

### 2. Supabase の設定
1. [Supabase](https://supabase.com) でプロジェクトを作成
2. `docs/setup_tables.sql` を Supabase の SQL Editor で実行
   - Phase 2.5 より前に作ったDBの場合は、代わりに `docs/migration_phase2_5.sql` を1回実行（列・テーブルの追加のみ。既存データは消えない）
3. `.streamlit/secrets.toml` を作成:
```toml
[supabase]
url = "https://your-project.supabase.co"
key = "your-anon-key"

[auth]
password = "your-app-password"
```

### 3. ローカル実行
```bash
streamlit run app.py
```

### テスト・DBなしでの画面確認
```bash
python -m unittest discover tests
```
```bash
streamlit run tests/preview_app.py
```
`tests/preview_app.py` はダミーデータ（乱数シード固定）で入力画面・集計画面を開く。Supabase には接続しない。

### 統計検定手法
- **カイ二乗検定**: クロス集計表の独立性検定に使用（2×2表ではイェーツの連続修正あり）
- **フィッシャーの正確確率検定**: 期待度数が5未満のセルが1つでも存在する場合に自動切替
  - 2×2表: 正確検定
  - 2×2より大きい表: Fisher-Freeman-Halton 検定。p値はモンテカルロ法（20,000回、乱数シード 20261015 固定）で算出するため、同じデータからは常に同じ結果になる
- **効果量**: クラメールの連関係数 V（連続修正なしのカイ二乗値から算出）
- 有意水準は5%。クロス集計は両方の設問に回答した人のみを対象とし、度数0の行・列は検定から除外

### 集計対象の絞り込み
- 調査区分（本調査／プレテスト）
- 鎌倉市内在住者（Q1=鎌倉市内）を「住民」として除外し、観光客のみで集計（既定）
- 回答者の範囲: 全回答者／一人客のみ／グループ代表1人（メンバー番号1）／グループ代表1人（ランダム抽出・乱数シード表示）
- 「同調の可能性あり」フラグの付いた回答の除外
- 適用順は 調査区分 → 住民除外 → 同調フラグ除外 → 代表者の選出。除外によってメンバー1が残らないグループは、残っている中で最小のメンバー番号の人を代表とする

### 調査の実施記録（回収率など）
- **回答率** = 回答した組数 ÷（回答した組数 ＋ 断られた件数）。声かけ1回 = 1組として数える。紙からの転記分は含めない
- 断られた記録には日時・調査地点・調査区分を記録し、地点別・時間帯別（日本時間）・日別に集計
- **所要時間** = 入力開始から保存までの秒数（現地入力のみ）。平均・中央値・最大を一人客／グループ客別にも算出
- **つまずきフラグ**: 回答者が迷った・意味が伝わらなかった設問に調査員が印を付ける（グループ単位で1件）。プレテスト後の設問修正に使う
- **回答方式**: 調査員が読み上げ／本人が記入 を回答者ごとに記録

### グループ回答の扱いと感度分析
- グループ客の各メンバーを個別の回答者として記録
- 回答の独立性を検証するため、以下の感度分析を実施:
  1. **全回答者集計**: グループメンバー全員を含む集計
  2. **グループ代表1人集計**: 各グループからメンバー番号1（または乱数シード固定のランダム抽出）を代表として選出した集計
- 両集計の結果を並列比較し、グループ回答が結果に与える影響を評価
- 「同調の可能性」フラグが付いた回答を除外した集計も実施可能

### 自由記述の分類方法
- コードブック（`config/codebook.yaml`）に基づく手動分類
- 1つの回答に複数カテゴリの付与が可能
- 分類者間の一致率はコーエンのκ係数で評価（Phase 5で実装予定）
- 集計は分類者 `classifier_1` の結果を使用。「保留」「新カテゴリ候補」はカテゴリ件数に含めない
